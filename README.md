# Контроль монтажа — МФК Фрунзенская наб.

Полноценное веб-приложение: авторизация с личным кабинетом (ФИО, должность, роль),
учёт монтажа кабелей/оборудования/щитов/контрольных точек с историей по датам,
учёт посещаемости объекта, выгрузка отчётов в Excel.

Стек: **Next.js** (бесплатный хостинг на Vercel) + **Supabase** (бесплатная база данных
Postgres с готовой авторизацией). Стоимость на вашем масштабе — **0 ₽/мес**.

---

## Шаг 1. Создать проект в Supabase (5 минут)

1. Зайдите на **supabase.com** → Sign up (можно через GitHub/Google) → **New project**
2. Задайте имя проекта, пароль базы данных (сохраните его отдельно), регион — выбирайте
   ближайший (например Frankfurt/Singapore — на бесплатном тарифе выбор ограничен)
3. Подождите ~2 минуты, пока проект создастся
4. Слева меню → **SQL Editor** → **New query**
5. Откройте файл `supabase/schema.sql` из этого проекта, скопируйте **весь** текст,
   вставьте в редактор и нажмите **Run**. Должно отработать без ошибок — создались
   все таблицы, права доступа и триггеры.
6. Новый запрос → откройте `supabase/seed_data.sql`, скопируйте весь текст, вставьте,
   **Run**. Это загрузит все проектные данные: 2062 кабеля, 607 позиций оборудования,
   57 щитов, 568 контрольных точек АДИС. Файл большой — выполнение займёт ~10-30 секунд,
   это нормально.
7. Слева меню → **Project Settings** (шестерёнка) → **API** — скопируйте:
   - **Project URL**
   - **anon public** ключ (НЕ service_role — его никуда не вставляем)

## Шаг 2. Включить подтверждение почты (или отключить, если не нужно)

**Authentication** → **Providers** → **Email** — по умолчанию Supabase требует
подтверждения почты при регистрации. Если хотите, чтобы монтажники сразу входили
без писем — выключите **Confirm email** в настройках Email provider.

## Шаг 3. Развернуть на Vercel (5 минут)

Вариант А — через GitHub (рекомендуется, тогда каждое обновление кода само
переразворачивается):
1. Создайте новый **пустой** репозиторий на github.com
2. Залейте туда содержимое этой папки (`git init`, `git add .`, `git commit`,
   `git remote add origin ...`, `git push`) — **не** коммитьте `.env.local`, если он
   у вас появится (он уже в `.gitignore`)
3. Зайдите на **vercel.com** → Sign up → **Add New Project** → выберите этот репозиторий
4. В разделе **Environment Variables** добавьте:
   - `NEXT_PUBLIC_SUPABASE_URL` = ваш Project URL из Supabase
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` = ваш anon ключ
5. **Deploy**. Через ~2 минуты получите ссылку вида `your-app.vercel.app` — это и есть
   рабочее приложение.

Вариант Б — без GitHub, через командную строку (если удобнее):
```bash
npm install -g vercel
cd install-control-app
vercel login
vercel
# на вопросы про переменные окружения — вставьте те же значения
vercel --prod
```

## Шаг 4. Первый вход и назначение администратора

1. Откройте ссылку приложения → **Зарегистрироваться** → укажите своё ФИО, должность,
   email, пароль
2. По умолчанию все новые пользователи получают роль **«Монтажник»**. Чтобы стать
   администратором (видеть управление пользователями, менять марки/длины кабелей):
   - зайдите в Supabase → **Table Editor** → таблица `profiles`
   - найдите свою строку (по email через таблицу `auth.users`, либо по ФИО)
   - в столбце `role` вручную поставьте `admin`
3. Дальше через раздел **«Профиль»** в самом приложении вы, как админ, можете менять
   роли остальным пользователям — заходить в Supabase больше не понадобится.

## Шаг 5. Свой домен (необязательно)

Vercel → ваш проект → **Settings → Domains** → добавьте свой домен (~150-1000 ₽/год
за регистрацию домена на любом регистраторе, привязка в Vercel бесплатна).

## Роли и права

| Роль | Может |
|---|---|
| **Монтажник** (installer) | Добавлять записи о монтаже (дата, количество, комментарий), отмечать расключение кабелей, статусы щитов/точек, отмечаться на объекте (посещаемость) |
| **Инженер** (engineer) | Всё то же + редактировать марку/длину/наименование кабелей и оборудования (если в проекте что-то поменялось) |
| **Администратор** (admin) | Всё то же + управление ролями пользователей |

## Как это устроено (коротко)

- `supabase/schema.sql` — вся структура БД: таблицы, права доступа (Row Level Security),
  представления для расчёта прогресса
- `supabase/seed_data.sql` — исходные проектные данные (кабели/оборудование/щиты/точки)
- `app/(app)/` — все экраны приложения после входа
- `app/login/` — вход и регистрация
- Каждая запись о монтаже — отдельная строка в `cable_logs`/`equipment_logs` с датой
  и автором: неограниченная история, в отличие от предыдущей версии на Claude Artifact,
  где было ограничение в 5000 документов

## Усиление прав (опционально, на будущее)

Сейчас редактирование марки/длины кабеля технически разрешено в БД любому
авторизованному пользователю (кнопка ✏️ просто скрыта в интерфейсе для монтажников).
Если нужно жёстко запретить это на уровне базы данных (не полагаясь на интерфейс),
попросите добавить Postgres-политику, проверяющую роль из таблицы `profiles`
непосредственно в правиле `cables_update`/`equipment_update`.

## Локальный запуск для разработки

```bash
npm install
cp .env.local.example .env.local   # вставьте свои ключи Supabase
npm run dev
# откройте http://localhost:3000
```
